# Linux Chaos Infrastructure non-root user installation

## 1. Create a non-root user (Requires root/sudo privileges)
```
sudo useradd --system --create-home --home-dir /home/linuxchaos linuxchaos
```

- `sudo`: Executes the command with superuser/administrative privileges
- `useradd`: The base command to create a new user account
- `--system`: Creates a system account (typically for running services/applications rather than for human users)
- `--create-home`: Creates a home directory for the user, for storing the infrastructure pre-requisites, logs and configs
- `--home-dir /home/linuxchaos`: Explicitly sets the home directory path to /home/linuxchaos
- `linuxchaos`: The username for the new account

## 2. Enable lingering (Requires root/sudo privileges)
```
sudo loginctl enable-linger linuxchaos
```

- `sudo`: Executes the command with superuser/administrative privileges
- `loginctl`: The systemd tool for managing user logins and sessions
- `enable-linger`: The specific operation that enables the lingering feature for a user
- `linuxchaos`: The username for which lingering should be enabled (the user we created in step 1)

User lingering is a Systemd feature that allows regular (non-root) users to run their own background services that persist even after the user logs out. Here's why it's necessary:

Without lingering enabled:
- A user's systemd services are started when they log in and terminated when they log out
- Background services owned by the user will stop when their session ends
- Automated services that need to run continuously won't survive a logout

With lingering enabled:
- The user's systemd services will start at boot and continue running regardless of login status
- Services can run persistently without requiring root privileges
- The user's systemd instance becomes independent of their login sessions

## 3. Install infrastructure
1. Login as the newly created user.

2. Create a new infrastructure while specifying that a non-root user should be used for the execution in the Harness UI and copy the installation command.

```
curl https://app.harness.io/public/shared/tools/chaos/linux/1.57.0/install.sh | sudo bash /dev/stdin --infra-id 5c2d6176-7v74-4fx1-9a44-63c4b68ae846 --access-key og6feh2cf02pcr3gwpgmkcfm0urt1xdx --server-url https://app.harness.io/gratis/chaos/lserver/api --non-root-user linuxchaos --no-sudo
```

3. Check for the status of the service:
```
systemctl --user status linux-chaos-infrastructure.service
```

# Troubleshooting

## The installation script execution fails
- The reason for the failure of the installation script is shall get mentioned as part of the stdout/stderr.
- Any error logs generated by the service will get logged to the `log/linux-chaos-infrastructure/linux-chaos-infrastructure.log` file inside the user's home dir (as opposed to Journald in case of the root user installation).

## Updating the service unit file
- The service unit file gets created at `.config/systemd/user/linux-chaos-infrastructure.service` in user's home dir.
- After modifying the unit file, reload the updated unit file and restart the service:
```
systemctl --user daemon-reload
systemctl --user restart linux-chaos-infrastructure.service
```

## Updating the config file
- The config file gets created at `config/linux-chaos-infrastructure/config.yaml`.
- After modifying the config file, restart the service:
```
systemctl --user restart linux-chaos-infrastructure.service
```
